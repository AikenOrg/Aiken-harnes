2026-11-07 時点で動く最小構成。`bun run check` と `bun test` が通る。

| JobManager | ジョブ ID、状態、タイムアウト、同時数上限、通知キュー、wait/cancel/read_result/list_jobs |
| PermissionBroker | 権限付与、ctx 呼び出し時の検査、ロール制約 |
| ModuleHost | manifest 検証、排他ロール、requires のトポロジカルソート、承認、critical/disabled |
| ModuleLoader | ディレクトリ / 単一ファイルの manifest 解決、動的 import |

## 同梱モジュール

- `src/modules/provider-mock` — `mock/echo` を返すプロバイダー
- `src/modules/tools-read` — `read` 同期ツール
- `src/modules/shell` — `shell` 非同期ツール（whitelist / full）
- `src/modules/provider-anthropic` — Anthropic Messages API プロバイダー
- `src/modules/provider-opencode-go` — OpenCode Go プロバイダー

## 動かす

```sh
bun install
bun run check
printf 'hello\n' | bun run src/index.ts --config config/dev.config.json --approve-all

# 実プロバイダー
ANTHROPIC_API_KEY=... bun run src/index.ts \
  --config config/anthropic.config.json --approve-all

# OpenCode Go (~/.config/next-harness/.env に OPENCODE_API_KEY を置く)
bun run src/index.ts --config config/opencode-go.config.json --approve-all
```

`--events` を付けると全イベントを表示する。Anthropic の raw ログは `logRaw: true` と `log.level: "debug"` で出す。承認 UI は M4 のため、現状は `--approve-all` で明示的に全権限を許可する。

## セキュリティ上の扱い

- shell の子プロセスには許可リストの環境変数だけを渡す。`OPENCODE_API_KEY` などは渡らない。
- read ツールは作業ディレクトリ外、`.env*`、`approvals.json`、秘密鍵、`.git`、`.ssh` を拒否する。シンボリックリンクは realpath 後に検査する。
- 秘密情報はプロジェクト外の `~/.config/next-harness/.env` (Windows は `%APPDATA%\next-harness\.env`) に置く。CLI が起動時に読み、既存の環境変数は上書きしない。
- shell の既定は whitelist。full は明示的に選んだ場合だけ。

## 実 API 検証 (2026-11-08)

`bun run verify:opencode-go` で OpenCode Go の実 API を検証。

- `cancel(id)` by ai: 長時間 shell が `cancelled`、`job.cancelled.by = "ai"`
- wait なしの完了通知: 次のモデル呼び出し前に履歴へ追加
- ストリーム途中のキャンセル: `interrupted: true` の部分応答が残る
- `contextWindow` 超過: モデルを呼ばず `turn.ended (context_overflow)`
- 壊れた tool args: fake provider で `tool.failed (invalid_args)` とエラー `tool_result` を確認

## 既知の制限

- `harness.send` はセッション単位で直列化する。複数セッションは並行可能。
- `HistoryManager` の読み取りスコープはモジュール権限で検査するが、セッション子孫の制限は M2 で詰める。
- `tool.before` の引数書き換えは再検証する。shell のホワイトリストは実装済み。承認 UI は M4。
- M1 の構成では result-store はメモリ実装。SQLite 永続化は M3 (`docs/impl/m3.md`) を参照。
- CLI は `--approve-all` なしだとモジュールを承認できないため起動しない。
- Anthropic / OpenCode Go 実装は SSE / 変換を fake fetch でテスト済み。
- OpenCode Go は実 API で以下を確認済み (2026-11-08): 単発応答、`read` ツール、非同期 shell → `wait` → `read_result` → 最終応答。API キーは環境変数経由のみで、リポジトリには保存していない。
- shell のホワイトリストは先頭トークンの basename 比較。シェル構文の完全な解析はしない（既知の受容リスク）。
- プロセスツリーの kill は Linux のプロセスグループと Windows の `taskkill /T /F`。Windows 実機は未検証。
