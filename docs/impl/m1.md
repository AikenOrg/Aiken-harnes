# M1 実装ノート

2026-11-07 時点で動く最小構成。`bun run check` と `bun test` が通る。

## 実装済み

| 領域 | 内容 |
|---|---|
| EventBus | `evt_<bootId>_<seq>`、発行順配信、ワイルドカード購読、購読者例外の隔離 |
| SessionManager | 作成・親子・状態（`restoring/active/idle/closed/error`）・再帰 close・closed のみ delete |
| HistoryManager | コアのメモリ履歴、追記・一括追記・読み出し・restore・rewrite |
| PromptAssembler | static → session → volatile、config 先頭、priority、キャッシュ境界、hash |
| ToolRegistry | zod 入力、sync/async 宣言、JSON Schema 生成、重複検査 |
| ProviderRegistry | モデル ID の接頭辞ごとの担当検査、`contextWindow` 必須 |
| JobManager | ジョブ ID、状態、タイムアウト、同時数上限、通知キュー、wait/cancel/read_result/list_jobs |
| PermissionBroker | 権限付与、ctx 呼び出し時の検査、ロール制約 |
| ModuleHost | manifest 検証、排他ロール、requires のトポロジカルソート、承認、critical/disabled |
| ModuleLoader | ディレクトリ / 単一ファイルの manifest 解決、動的 import |
| TurnLoop | ストリーミング、tool_call、同期/非同期ツール、通知の末尾追記、context_overflow |
| Hooks | `prompt.assemble` / `tool.before` / `compaction.decide` の登録と実行 |
| CLI | config からモジュールをロードし、stdin で対話 |

## 同梱モジュール

- `src/modules/provider-mock` — `mock/echo` を返すプロバイダー
- `src/modules/tools-read` — `read` 同期ツール

## 動かす

```sh
bun install
bun run check
printf 'hello\n' | bun run src/index.ts --config config/dev.config.json --approve-all
```

`--events` を付けると全イベントを表示する。承認 UI は M4 のため、現状は `--approve-all` で明示的に全権限を許可する。

## 既知の制限

- `harness.send` はセッション単位で直列化する。複数セッションは並行可能。
- `HistoryManager` の読み取りスコープはモジュール権限で検査するが、セッション子孫の制限は M2 で詰める。
- `tool.before` の引数書き換えは再検証するが、shell のホワイトリストは shell モジュール実装時。
- result-store はメモリ実装。再起動復元と TTL は SQLite 実装時。
- CLI は `--approve-all` なしだとモジュールを承認できないため起動しない。
