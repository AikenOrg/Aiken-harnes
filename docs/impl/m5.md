# M5 実装ノート: 最小の Web UI

2026-11-08 時点。`ui-web` モジュールと `ui` ロール向け API を実装した。

## 1. 追加したコア API

`ui` ロールは全セッションを扱えるが、必ず `ctx` を通す。

- `ctx.session.list()` / `models()`
- `ctx.session.send(sessionId, text)` / `cancel(sessionId, opts?)`
- `ctx.jobs.list(sessionId, status?)` / `read(jobId, {offset, limit})` / `cancel(jobId, opts?)`
- 追加権限: `session.input` / `job.read` / `job.cancel`

`ctx.session.close` / `delete` は Harness の完全な後始末へ委譲した。`delete` は `closed` のみ。`user` キャンセルは `user.cancel` を発行する。

## 3. 安全対策

- 既定 bind は `127.0.0.1`。`0.0.0.0` は警告のみで、Origin/Host は loopback 固定。
- WebSocket の `Origin` は `http://127.0.0.1:PORT` / `http://localhost:PORT` のみ。`Origin` なしは許可。
- `Host` は `127.0.0.1:PORT` / `localhost:PORT` のみ。
- HTTP は `GET` / `HEAD` だけ。`POST` などは 405。
- CORS ヘッダーを返さない。CSP / nosniff / frame deny / no-referrer を付ける。
- トークン認証はなし。同一マシンの他プロセスは接続できるため、共有マシンでは使わない。

`0.0.0.0` を指定しても LAN からは Host 検証で拒否される。リモート利用は M6 以降の課題。

## 4. プロトコル

- サーバー → クライアント: `snapshot` / `event` / `approval.request` / `approval.resolved`
- クライアント → サーバー: `{id, type, payload}`、応答は `{id, ok, result|error}`
- 再接続は snapshot の取り直しのみ。イベント再送はしない。
- `model.delta` は 40ms バッチ。同一ターンの終端イベント前にフラッシュする。
- 承認は接続前でも保留でき、snapshot に含める。既定 5 分でタイムアウト拒否。

詳細は [../spec/15-web-ui.md](../spec/15-web-ui.md)。

## 5. 画面

- 左: セッションの木、状態チップ、新規 / 復元 / 閉じる / 削除
- 中央: モデル切り替え（セッション単位、次のターンから）、メッセージ、ツール呼び出し / 結果の折りたたみ、interrupted、ストリーミング、入力、キャンセル
- 右: ジョブ（キャンセル / 結果）とイベント（種別フィルタ、新しい順）
- モーダル: モジュール承認

`@material/web` は `client/components.ts` のラッパーだけから使う。画面コードに `<md-*>` の直書きはない。色は `seedColor` からライト / ダークを生成し、`prefers-color-scheme` に従う。

## 6. CLI

- `ui-web` を含む構成では REPL を起動せず、ヘッドレスで待機する。
- `ui-cli` 構成の REPL は残す。
- Ctrl+C は現在のターンをキャンセルする。2 秒以内に 2 回押すと終了する。

## 8. テスト

`tests/modules/ui-web.test.ts`:

- `Origin` / `Host` の許可判定
- 異なる Host の HTTP、異なる Origin / Host の WebSocket ハンドシェイク拒否
- `POST` の 405
- `Origin` なし WebSocket の 101
- 静的 HTML / テーマ CSS / クライアントバンドル
- snapshot → セッション作成 → 送信 → キャンセル → ジョブ一覧
- モデル切り替えコマンドと `session.model` イベント
- 承認の要求 → 応答
- 接続前の承認が snapshot に含まれること

実ハーネス + WebSocket:

- 実行中ターンのキャンセルで、部分応答が `interrupted` 付きで履歴に残る
- 実行中 shell ジョブを UI からキャンセルできる
- 親 + 子 2 のセッション木を snapshot から選び、子の履歴を読める

手動で確認済み:

- 実プロセス起動、HTTP 200 / `app.js` 200 / POST 405 / 異 Host 403
- WS で snapshot → create → send → turn.ended → history
- 実 API (OpenCode Go): `read` ツールを 1 回使い、`model.delta` を配信して `turn.ended (completed)`
- 承認モーダルの承認で `demo-tool` がロード、拒否でロードされない
- `--approvals` を分離して両方を確認
- ヘッドレス Chromium で画面を読み込み、`md-list-item` / `md-tabs` / `md-outlined-text-field` の描画、セッション ID、状態チップ、WS 接続を確認

## 9. 未確認・制限

- 実ブラウザでの目視による細部（余白、ダークモードの見え方）は未確認。ヘッドレス Chromium の DOM とスクリーンショットまでは確認済み。
- スマホ、複数ユーザー、リモートアクセスは対象外。
- 履歴の編集、ファイルビューア、ログ検索は対象外。
- `0.0.0.0` を指定しても LAN からは接続できない（Origin/Host は loopback 固定）。
