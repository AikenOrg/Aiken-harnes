# 01. 全体像

## 1. 目的

AI エージェントの「ハーネス」をゼロから自作する。特定のモデル提供者・UI・保存先に縛られず、**コアのループは小さく保ち、能力はすべてモジュールで足す**ことを狙う。

- コア: AI とのループ、モデル選択、イベントバス、モジュールロード、セッション ID、ジョブ ID と状態。
- モジュール: プロバイダー、ツール (read / write / shell)、ログ、履歴・セッション永続化、compaction、UI (Web / TUI)。
- 通信: すべてイベントバスと `ctx` 経由。モジュール同士は `talksTo` で宣言した相手としか話せない。

## 2. スコープ

| 含む | 含まない (現時点) |
|---|---|
| コアのターンループとストリーミング | モデルごとの高度な最適化 |
| モジュールの manifest / 権限承認 | fs / net / env / exec の実サンドボックス |
| 同期・非同期ツールとジョブ管理 | 外部リポジトリからのモジュール取得 |
| プロンプト断片の結合とキャッシュ境界 | compaction の詳細アルゴリズム |
| SQLite による履歴・ジョブ結果の保存 | チーム機能 (別途、モジュール側) |
| WebUI / TUI をモジュールとして接続 | マルチプロセス分散実行 |

## 3. 設計原則

1. **コアはオーケストレーターに徹する。** モデル呼び出し・永続化・UI の実装を持たない。コアが持つのは制御・状態遷移・実行中履歴だけ。
2. **能力はモジュール、境界は権限。** 何ができるかは manifest で宣言し、ユーザーが承認する。コア API 系の権限は `ctx` で実効的に強制する。
3. **安定したものから順にプロンプトへ。** static → session → volatile の順に結合し、キャッシュ境界をコアが管理する。ターン途中で履歴の先頭を書き換えない。
4. **通知は末尾にだけ足す。** 非同期ジョブの完了通知は次のモデル呼び出し直前に履歴の末尾へ追記する。既存プレフィックスのキャッシュを壊さない。
5. **重い処理は非同期。** ツールは ID を返して終了し、完了・失敗・キャンセルはイベントと通知で返す。read などの軽い処理だけ同期。
6. **落ちて良いものと悪いものを分ける。** `critical` なモジュールの障害は即停止。それ以外は `module.disabled` にして継続する。
7. **OS 非依存。** Linux / Windows の両方で動く。パス・シェル・シグナルはモジュール側で吸収する。

## 5. 実行時モデル

- 1 プロセス内でコアとモジュールを動かす (`runner: "inprocess"` のみ)。
- コアはサーバーとして動き、UI はクライアント兼モジュールとして接続する。WebUI は HTTP/WS、TUI は同一プロセス内のイベント購読を想定する (トランスポートは UI モジュールが決める)。
- 1 セッション内のターンは直列。複数セッションと非同期ジョブは並行して進む。
- **実行中の履歴はコアがメモリに保持し、それが唯一の正。** history-store は `message.appended` を購読して書き出す投影であり、必須ではない。
- セッションと履歴の永続化は任意モジュール (SQLite など) が担う。コアは保存先を知らない。

## 6. 用語

| 用語 | 定義 |
|---|---|
| セッション | 会話の単位。`id` / `parentId` / `state` / `model` をコアが保持する |
| ターン | ユーザー入力 1 回に対するモデル呼び出し〜ツール実行〜最終応答のまとまり |
| ジョブ | 非同期ツール実行の単位。コアが ID を発行し、状態を管理する |
| 断片 (fragment) | システムプロンプトの一部分。優先度と安定度を持つ |
| モジュール | manifest を持つ拡張単位。ロールと権限を宣言する |
| ロール | モジュールの役割。一部は排他 (同時に 1 つ) |
| 権限 (capability) | モジュールが要求する操作許可。承認後に `ctx` で使う |
| フック | コアの処理に割り込み、結果を変えられる拡張点 |
| 通知 | 非同期ジョブの完了をモデルへ伝える固定 JSON |

## 7. 技術スタック

| 項目 | 決定 |
|---|---|
| 言語 / ランタイム | TypeScript / Bun 1.4 系 |
| 型検査 | `tsc --noEmit` (strict) |
| スキーマ | zod (ツール入力・設定検証) |
| DB | SQLite (Bun 組み込み `bun:sqlite`) を任意モジュールが保持 |
| テスト | `bun test` |
| 対応 OS | Linux / Windows (パス区切り・シェル差異はモジュールで吸収) |

## 8. 完成の最小定義

「read → 非同期 shell → wait → 完了通知 → モデルが結果を読む」が、コアのメモリ履歴と 1 つのプロバイダーだけで最後まで動くこと。永続化モジュールは後から足せる。評価タスクは [13-roadmap.md](13-roadmap.md) を参照。
