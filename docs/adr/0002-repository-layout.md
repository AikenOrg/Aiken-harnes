# ADR 0002: リポジトリ構成とドキュメント優先

- 日付: 2026-11-07
- 状態: 採用

## 文脈

コアとモジュールを分離する設計だが、初期段階で monorepo (workspace) にすると、型参照とビルドの設定が増える。実装は AI が反復的に進めるため、1 コマンドで型検査とテストが回ることを優先したい。

## 決定

- 単一パッケージ構成とする (`packages/` に分割しない)。
- 共有契約は `src/protocol/` に置き、コアとモジュールの双方から参照する。
- コアは `src/core/`、組み込みモジュールは `src/modules/`。
- モジュールは実行時にパスからロードし、コアは特定モジュールを import しない。
- 仕様は `docs/` に置き、原文スペックを `docs/requirements/original-spec.md` に保存する。
- 実装より先に docs を更新する (docs-first)。

## 理由

- `bun run check` だけで全体を検証できる。
- モジュールの境界はパッケージ境界ではなく、`ctx` と manifest で表現する。ディレクトリ分割は後からでもできる。
- 原文と派生仕様を分けることで、解釈の drift を検出しやすい。

## 影響

- 将来 workspace に分割する場合、`src/protocol` を独立パッケージへ移す。
- モジュールの配布は「単一ファイルまたはディレクトリ + manifest」を想定する。
- `docs/spec/14-open-decisions.md` に補完事項を集約し、実装前に確認する運用とする。
